# RGBlink VUE / Bitfocus Companion PoC

A VISCA command generator and Bitfocus Companion module skeleton for RGBlink VUE RGB30X-POE-TLY cameras. This repository separates offline command checks from the live transport validation still needed on a physical camera.

## Try it without hardware

Use Node.js 22.20+ (the module declares Node 22 support). The offline tests need no dependencies, network access, or camera:

```sh
git clone https://github.com/kalidatuna/rgblink-vue-companion-poc.git
cd rgblink-vue-companion-poc
node test.js
node companion-module/test/protocol.test.js
node companion-module/test/actions.test.js
```

Generate a command without sending anything:

```js
const { Commands } = require('./visca')
console.log(Commands.presetRecall(5).toString('hex').toUpperCase())
// 8101043F0205FF
```

## Included functionality

The command layer covers power, pan/tilt and HOME, variable zoom and focus, autofocus, exposure, iris, white balance, backlight, presets, and red/green tally. Tests compare generated bytes with the packet fixtures in this repository.

The Companion skeleton includes 12 actions, host/port/camera-ID configuration, and `last_command_hex` and `send_mode` variables. Dry-run mode is enabled by default. See [module help](companion-module/companion/HELP.md) for configuration and [pilot-actions.json](pilot-actions.json) for the pilot action list.

## Validation boundary

The existing protocol implementation uses port **3001** by default and presets **0–254**, based on the RGBlink manual used for this proof. The tests check packet construction and action callbacks; they do not prove camera compatibility or validate the complete Companion runtime.

Raw UDP is exposed as a live-test mode. IP framing, acknowledgement handling, firmware behavior, and physical camera operation still require validation. A successful UDP send does not confirm that a camera accepted a command. Keep dry-run enabled until the transport is verified for the intended camera.
